Where the frames come from

Live capture is the quickest way to try this, and the lower-quality one: a browser is usually given less resolution than the camera app records at. The page shows you how many camera pixels are landing on each cell, which is the number that decides whether it can work at all. If it is low, step closer.

Recorded with the camera app, this gets the full sensor resolution, which is what the format was designed around.

Nothing is uploaded either way. Everything is read on this device.

Settings

Leave this alone. The frames say which profile drew them, so there is nothing to match between the two devices.

Once started this reads until it has the whole file, then stops on its own and offers it to you. It does not matter that you joined the sender halfway through — it keeps going into the next pass. "Give up" is only there for when you want to stop early and see how far it got.

If it does not work

This page reports which stage gave up, not just that it failed. The three common outcomes have different fixes:

  • Too few pixels per cell — below about five, the shapes in each cell stop being separable no matter what else is right, and error correction cannot invent detail that was never recorded. Step closer, or switch to recording with the camera app and loading the file here.
  • Caught mid-change — the sending screen is changing faster than this camera can capture a whole code, so each picture is half of one and half of the next. Raise "hold each code" on the sending device. This is the usual outcome when filming a computer monitor with a phone.
  • The code was not found in most frames — the screen is too blurred or too reflective. Hold steadier and move the glare off it.
  • Not enough blocks — you simply stopped too early. Keep going; the sender never repeats itself, so every extra second is new data.

Sending a picture for diagnosis

If it keeps failing, this page offers one of the pictures it could not read, exactly as the decoder saw it. Run it through the command line and it will print every measurement it took: 

photon decode picture.png

A directory of pictures works too, and neither needs ffmpeg.
